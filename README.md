# NOVA — Технології майбутнього

Навчальний вебсайт Варцаби Ростислава Павловича для лабораторної роботи №8 з дисципліни «Основи комп'ютерної інженерії». Автор родом із села Косівська Поляна, навчається в ТНТУ ім. І. Пулюя за спеціальністю «Комп'ютерна інженерія», група СІ-11.

**Тема сайту:** технології майбутнього — штучний інтелект, робототехніка та цифрові інновації.  
**Варіант завдання:** №4.

## Опублікований сайт

Після ввімкнення GitHub Pages замініть адресу нижче на фактичне посилання, яке GitHub покаже в **Settings → Pages**:

`https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/`

> Посилання залишено як шаблон, оскільки ім'я GitHub-користувача та URL репозиторію не вказані в матеріалах завдання.

## Структура сайту

- `index.html` — головна сторінка з інформацією про автора та тематикою сайту.
- `task.html` — виконане завдання для варіанта №4: матриця взаємних курсів шести валют розміром 6 × 6.
- `team.html` — сторінка з точним заголовком **«Учасники моєї команди»** та порожнім списком для майбутніх посилань.
- `assets/style.css` — спільне адаптивне оформлення всіх сторінок.
- `assets/favicon.svg` — іконка сайту.

Усі три HTML-сторінки мають спільне навігаційне меню з посиланнями одна на одну.

## Розрахунок варіанта №4

За умовою, якщо `N mod 4 = 0`, потрібно виконати завдання 4 — матрицю курсів валют із набором №2.

Для `N = 4` у таблиці варіантів зазначені індекси додаткових валют **0, 6, 7**. У наборі №2 це відповідно:

| Індекс | Валюта |
|---:|---|
| 0 | NZD — новозеландський долар |
| 6 | SGD — сінгапурський долар |
| 7 | ZAR — південноафриканський ранд |

Разом шість валют матриці: **UAH, USD, EUR, NZD, SGD, ZAR**.

### Як читати матрицю

Таблицю побудовано HTML-тегами `table`, `thead`, `tbody`, `tr`, `th` і `td`, а заголовки об’єднано атрибутами `colspan` та `rowspan` за зразком із методичних вказівок: у верхній частині вказано **«Варіант 4»** і **«Купівля 25.11.2026»**, ліворуч — **«Продаж 25.11.2026»**. У стовпцях розміщено валюти купівлі, у рядках — валюти продажу.

У клітинці на перетині **рядка A** та **стовпця B** показано, скільки одиниць валюти A потрібно для купівлі однієї одиниці валюти B. Якщо `R(A)` та `R(B)` — базові курси валют A і B до гривні, то:

`K(A, B) = R(B) / R(A)`

Наприклад, у рядку UAH та стовпці USD вказано 45,35410000: це означає, що 1 USD = 45,3541 UAH. На головній діагоналі матриці всі значення дорівнюють 1. Взаємні курси розраховано з базових курсів і відображено з точністю до 8 знаків після коми.

## Як завантажити сайт у свій репозиторій

1. Розпакуйте архів із сайтом.
2. Скопіюйте **вміст** папки `lab8_variant4_NOVA_final` у кореневу папку свого клонованого репозиторію — поруч із папкою `.git`. Не копіюйте проєкт у ще одну вкладену папку.
3. Переконайтеся, що структура репозиторію має такий вигляд:

   ```text
   your-repository/
   ├── .git/
   ├── .gitignore
   ├── LICENSE
   ├── README.md
   ├── index.html
   ├── task.html
   ├── team.html
   └── assets/
       ├── favicon.svg
       └── style.css
   ```

4. У терміналі, відкритому в кореневій папці репозиторію, виконайте:

   ```bash
   git status
   git add .
   git commit -m "Create NOVA website for lab 8"
   git push origin main
   ```

## Як увімкнути GitHub Pages

1. Відкрийте свій репозиторій на GitHub.
2. Перейдіть у **Settings → Pages**.
3. У **Build and deployment** виберіть **Deploy from a branch**.
4. Як гілку виберіть `main`, а папку — `/(root)`, після чого натисніть **Save**.
5. Дочекайтеся завершення публікації. GitHub покаже адресу сайту в цьому ж розділі.
6. Вставте отриману адресу в розділ **«Опублікований сайт»** цього README та зробіть ще один коміт і `git push`.

## Перевірка через W3C Validator

Після публікації відкрийте [validator.w3.org](https://validator.w3.org/) і перевірте **кожну сторінку окремо**: `index.html`, `task.html` та `team.html`. Виправте всі помилки, якщо валідатор їх знайде. Фінальний результат перевірки потрібно зберегти для звіту.

## Посилання на репозиторії учасників через Pull Request

Цей пункт виконується після обміну посиланнями з іншими учасниками групи:

1. Попросіть кожного учасника надіслати URL свого GitHub-репозиторію та опублікованого сайту.
2. У репозиторії кожного учасника створіть окрему гілку, наприклад `add-rostik-links`.
3. Додайте до його README посилання на ваш репозиторій і сайт, наприклад:

   ```markdown
   - [Ростислав Варцаба — репозиторій](https://github.com/YOUR-USERNAME/YOUR-REPOSITORY)
   - [Ростислав Варцаба — сайт](https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/)
   ```

4. Створіть коміт, відправте гілку на GitHub та відкрийте Pull Request до основної гілки учасника.
5. Повторіть процедуру окремо для кожного учасника. Їхні імена та URL не додані наперед, щоб не вигадувати посилання.

## Примітка

GitHub Pages, фактичне посилання в README, перевірка опублікованих сторінок через W3C Validator та Pull Request до репозиторіїв одногрупників потребують дій у вашому GitHub-акаунті й даних інших учасників. Цей архів містить підготовлені файли сайту та інструкції для цих кроків.
